Incident evidence for decentralized compute

A signed record of what happened when a GPU host went down.

Incident Witness collects bounded observations from the provider's host, the renter's workload client and a separately operated platform probe. It correlates them into a portable bundle that can be verified offline.

Three sources

Separate observations. One correlatable record.

Each source has its own key, its own scope and its own view of the incident. None of them is treated as a complete account on its own.

Host agent Provider

Provider host

An unprivileged Linux agent records host heartbeats, GPU telemetry availability, UPS state transitions and agent status using fixed collectors.

  • Bounded, typed event payloads
  • Durable local spool with retry
  • No remote shell or arbitrary commands

HOST-SIGNED · ED25519 · INCIDENT-SCOPED

Renter client Renter

Workload client

An incident-scoped TypeScript SDK runs in the renter's workload and records workload heartbeats plus endpoint reachability results.

  • One-use invitation enrollment
  • Incident-scoped signing key
  • Explicit unreachable and gap states

RENTER-SIGNED · INCIDENT-SCOPED

Platform probe Platform

Platform-operated probe

A separate background worker checks the provider's verified public endpoint using a fixed HTTPS GET. It is operated by the platform, not an independent third party.

  • DNS-verified public hostname only
  • Pinned address, no redirects or proxies
  • Bounded result categories and latency

PLATFORM-OPERATED · NOT INDEPENDENT

Offline verification

Check the bundle without trusting the server.

A sealed bundle contains the manifest, source certificates and signed observations. The local verifier recomputes the digests and checks every signature in the browser.

  • ✓ Canonical manifest digest and platform signature
  • ✓ Source certificates, key scope and event signatures
  • ✓ Deterministic event order, sequence and capture-window bounds
  • ✓ Explicit simulation labels and evidence gaps

Signature verification confirms integrity and provenance from a key. It does not prove sensor truth or root cause.

What the evidence can and cannot do

Useful for reconstructing a timeline. Not an outage verdict.

It can help support

A source-attributed sequence of observations, a deterministic evidence pattern and tamper detection against the sealed bundle.

It cannot establish

Sensor truth, physical root cause, fault or intent, or whether a marketplace should excuse downtime or change a reliability score.

The platform probe is a platform-operated source, not an independent third party. Missing UPS, GPU, renter or probe observations are represented as gaps or unavailable data — never as normal.
